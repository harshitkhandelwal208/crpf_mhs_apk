# CRPF Mental Health Support Platform

[![Deploy FastAPI to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/harshitkhandelwal208/crpf_mhs_apk)

A shared wellbeing platform for CRPF personnel with:

- an Android personnel application;
- a standalone Windows admin console;
- a FastAPI service shared by both clients; and
- PostgreSQL/Neon persistence owned exclusively by the backend.

The application supports personnel authentication, journaling, queued offline
sync, support resources, operational alerts, permission-gated clinical access,
and audited administration.

> This is an early-support and demonstration platform, not a diagnostic system.
> The admin monitoring screen uses synthetic values only. It does not connect to
> cameras, microphones, or keystroke collection.

## Architecture

```text
Android app ───────────────┐
                           ├── HTTPS ── FastAPI ── PostgreSQL / Neon
Windows admin executable ──┘
        (local Next.js BFF)
```

Neither client contains database credentials or connects directly to
PostgreSQL. The Android app calls FastAPI, while the admin renderer calls a
local Next.js BFF that stores FastAPI JWTs in HTTP-only cookies.

## Project layout

- `app/` — Android application
- `backend/` — shared FastAPI API and database models
- `admin-website/` — Next.js admin console and Electron packaging
- `render.yaml` — Render deployment definition for FastAPI

## Backend setup

The backend reads configuration, in increasing precedence, from:

1. root `env`;
2. root `.env`;
3. `backend/.env`; and
4. process environment variables.

Create one of the ignored environment files for local development:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require
SECRET_KEY=replace-with-a-long-random-production-secret
ENV=development
DEBUG=false
```

Never copy `DATABASE_URL` into the Android app, Next.js public variables, the
Electron installer, or source control.

Run locally on Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
Set-Location backend
python manage.py migrate
python seed.py
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

The API documentation is available at `http://127.0.0.1:8000/docs` and the
health endpoint at `http://127.0.0.1:8000/health`.

## Deploy FastAPI to Render

Commit and push the deployment files before opening the **Deploy to Render**
button above. Render reads the root `render.yaml`, deploys the service in
Singapore, runs Alembic migrations before each release, and checks both API and
database readiness at `/health/ready`.

Render prompts for these values during the initial Blueprint deployment:

| Variable | Value |
|---|---|
| `DATABASE_URL` | The existing Neon PostgreSQL URL from the local `env` file |
| `BOOTSTRAP_ADMIN_EMAIL` | A real email for the first super administrator |
| `BOOTSTRAP_ADMIN_PASSWORD` | A unique 16+ character password with upper, lower, number, and symbol |

`SECRET_KEY` is generated by Render and must not be copied from the local
development environment. The administrator is created once by the initial
deploy hook; the hook never overwrites an existing account. Remove the two
bootstrap credential variables from the Render service after the first account
has been verified.

Do not run `seed.py` against Neon in production because it creates known
fictional development credentials. Use the resulting Render HTTPS URL as
`SENTINEL_API_BASE_URL` for Android and `BACKEND_API_URL` for the desktop admin
application.

## Android app

Debug builds default to the Android emulator host at
`http://10.0.2.2:8000/`. Override the API origin with the
`SENTINEL_API_BASE_URL` Gradle property or environment variable.

A release build requires a credential-free HTTPS origin:

```powershell
.\gradlew.bat assembleRelease -PSENTINEL_API_BASE_URL=https://api.example.gov.in/
```

For local validation:

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

The debug APK is written to `app/build/outputs/apk/debug/app-debug.apk`.
Release builds enable code and resource shrinking. Journals are stored locally
with bounded history and synchronized through WorkManager using stable request
IDs, making retries safe after connectivity interruptions.

## Windows admin application

Install dependencies and create an x64 NSIS installer:

```powershell
Set-Location admin-website
npm install
npm run lint
npx tsc --noEmit
npm run desktop:dist
```

The installer is written to
`admin-website/dist-desktop/CRPF-MHS-Admin-0.2.1-x64-Setup.exe`.

Configure its API origin with the `BACKEND_API_URL` environment variable, or
create `%APPDATA%\CRPF MHS Admin\desktop-config.json`:

```json
{
  "BACKEND_API_URL": "https://api.example.gov.in"
}
```

Production URLs must use HTTPS. The executable starts its bundled Next.js
server on a dynamically selected `127.0.0.1` port only. It does not listen on a
LAN/public interface or add firewall rules, so it should not require recurring
inbound network permission. See
[`admin-website/docs/DESKTOP.md`](admin-website/docs/DESKTOP.md) for packaging
and security details.

## Privacy and access controls

- Administrators do not automatically receive journal, conversation, or
  assessment access.
- Clinical content is permission-gated and sensitive access is audited.
- Android access and refresh tokens use encrypted preferences.
- Admin access and refresh tokens remain in HTTP-only BFF cookies.
- The demonstration monitoring view is explicitly synthetic and performs no
  CCTV, audio, sleep-device, or typing telemetry ingestion.
